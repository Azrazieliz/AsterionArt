# Asterion creative app merge assessment

Art, Writer, Sound and Foundry can share a project workspace and timeline while retaining their specialist engines. Start from Art's Studio and add project entry points around the engines as their contracts mature. Nexus remains the canonical library and cache. Control coordinates approved cross-app operations. NoWorld decides whether a world asset can be ingested and activated.

## Merge boundary

Share the project library, selection, timeline, navigation and job status experience first. A project should retain the Writer chapter revision, Art creation and draft IDs, Nexus asset hashes, Sound track IDs and Foundry revision or receipt IDs as their producers expose them. Art owns the visual timeline and final media export. The contributing engines can resume work from their own durable receipts.

The checked peers use separate app identities and stores. A combined APK would use one identity, while the standalone apps have private stores and signing histories. Test export and versioned import on copied projects with both standalone apps still available before any owner-device cutover. The current reference and media handoffs are the first slice. They require no production package migration. [Android app signing](https://developer.android.com/studio/publish/app-signing)

The source inspection establishes available interfaces. Release installation, provider permissions on the Samsung, direct service connectivity and finished visual quality require their own evidence. The isolated Studio build verifies the UI path without replacing the installed Art package.
