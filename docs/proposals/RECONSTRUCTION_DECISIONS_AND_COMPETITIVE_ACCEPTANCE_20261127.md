## Proposed technical responsibility split

1. Mode-native executable graphs with fixed typed inputs, native operations, immutable source/identity constraints and exact output contracts. No runtime methodology reading, generic chat reasoning, or creative sentence templates.
2. Learned shared concept/reference encoder plus independently specialized output heads or modules, compared against fully separate specialist models. A design representation uses typed structural attributes and learned features; preserve required data through a trained, model-specific conditioning projection, not an arbitrary latent injection. User directive text is allowed as task data. Train and evaluate all proposed structures.
3. Three independent tailored image foundations. Compare base quality, conditional reference channels, refinement support and Android deployment. Use architecture-compatible fine-tuning/fusion only. No required runtime LoRA catalogue; optional adapters must demonstrate measurable additional value. On low-resource hardware prioritize parameter-efficient experiments and small task-specific learned operators. Free GPU training scope/data policy is an owner decision.
4. Evidence-aware sheets: retain originals, visible board, role-specific typed observations, source crop/region mappings and model-specific feature caches. Do not equate style analysis with identity transfer. Rebuild caches on encoder change. Existing one-shot Character Sheet contract remains unless individually changed.
5. Native video: retain existing 10–30s contract unless owner expands it; benchmark Wan and other local engines against source clips for motion, temporal identity, style, camera coherence and continuity. Multi-shot production and audio scope are open; do not claim clip concatenation provides long temporal conditioning.
6. Existing Artwork five phases with N candidates per phase and exactly one continuation. Other modes keep independent contracts. Evaluate raw and finished outputs. Keep immutable source/reference/output provenance. Learning must use approved grades; automatic update scope remains open.

## Competitive benchmark

Baseline competitors: Local Dream (https://github.com/xororz/local-dream), Nightmare Mobile (https://github.com/AbrahamPaulJ/nightmare-mobile). Pin installed versions and supported features at test time. Compare matched-device, matched-model, resolution/seed/conditioning/compute-budget cases where possible, plus each system's best complete achievable result under the same elapsed-time budget. Record native settings, all source roles, raw and final artifacts, time, RAM, thermal state, retries, failures, and required user interventions. Do not count unavailable comparator functions as image-quality losses; score capability coverage separately. No fake outputs.

Proposed benchmark initial sample: 30 matched image cases per independent family spanning easy and hard reference tasks, with repeated seeds for critical cases, and separate held-out mode-specific acceptance cases. Compare blind paired preferences for final visual quality and reference fidelity, strict hard-schema compliance, useful-image completion rate, active user effort, latency and resource consumption. Proposed superiority gate: majority preference with a confidence interval above chance on the representative held-out set, no material regression in protected criteria; exact quantitative thresholds and review burden require calibration. Native device testing, real outputs and per-mode hard contracts are required. Five-minute pre-generation is acceptable if justified by quality, not a fixed limit. No sphere-based release acceptance. Do not claim beating human artwork or commercial tools without evidence.
