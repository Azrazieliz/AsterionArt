# WEAPON CREATION — ABSOLUTE AUTHORITATIVE CREATIVE WORKFLOW

## Version 1.0 — Character-Frozen / Signature-Weapon / Catalogue-to-Final Workflow

**STATUS:** AUTHORITATIVE / STANDALONE / CHARACTER-SPECIFIC / PREMIUM-ANIME-MANHWA-GACHA / CATEGORY-READABLE / SIMPLE-MACRO-INTRICATE-MICRO / 2D-NATIVE / IMAGE-CAPABLE

This document is the sole authoritative Weapon Creation workflow for the active conversation.

Its purpose is to create visually distinctive fictional weapons for an already-established character without redesigning the character, the frozen outfit, or any other upstream identity system.

This is a **visual concept-design workflow**, not a real-world fabrication, engineering, or construction manual. Do not provide operational dimensions, manufacturing tolerances, assembly procedures, or other instructions intended to make a real weapon functional.

---

# 0. HIGHEST-PRECEDENCE EXECUTION LOCK

Weapon Creation follows:

**FROZEN CHARACTER (+ OPTIONAL FROZEN OUTFIT) → CHARACTER / OUTFIT ANALYSIS → WEAPON-CATEGORY SEARCH → SIMPLE CONVENTIONAL VISUAL BASE → CATEGORY-READABILITY LOCK → CHARACTER-SPECIFIC STRUCTURAL TRANSFORMATION → MATERIAL + COLOR ARCHITECTURE → SIMPLE-MACRO / INTRICATE-MICRO PASS → RENDER PREFLIGHT → IMAGE GENERATION → ACTUAL-IMAGE INSPECTION → USER SELECTION / FUSION / ALTERATION / FREEZE**

The source character is immutable unless the user explicitly leaves Weapon Creation and requests a character redesign.

If an outfit is supplied as frozen, it is also immutable unless the user explicitly requests an outfit change outside this workflow.

The weapon adapts to the character.

The weapon adapts to the outfit when relevant.

The character and outfit do not change to make the weapon easier to design.

# 1. REQUIRED INPUT

A normal Weapon Creation task requires a character authority.

Valid inputs include:

- a character illustration;
- a Character Sheet;
- a frozen Character Creation output;
- a frozen Feminisation output;
- another explicit visual character reference.

An Outfit Creation output may also be supplied and becomes a frozen secondary authority for:

- hand / glove interfaces;
- gauntlets;
- sleeve clearance;
- carrying positions;
- scabbard / holster / sling interfaces;
- silhouette balance;
- material relationships;
- color relationships.

An outfit is helpful but not mandatory.

If an Art Style Sheet is supplied, it governs rendering style only.

---

# 2. CHARACTER FREEZE — HARD / ABSOLUTE

Preserve:

- face identity;
- head;
- eyes;
- hair;
- body proportions;
- body scale;
- shoulder structure;
- arm length;
- hand size;
- hand anatomy;
- species anatomy;
- claws / extra digits / unusual hands;
- appendages;
- body-integrated structures;
- permanent asymmetry;
- existing silhouette;
- concept-derived anatomy.

The character may hold, carry, wear, suspend, mount, or interact with a weapon.

The weapon may never require:

- resized hands;
- different arm proportions;
- altered anatomy;
- moved appendages;
- deleted claws;
- changed body scale;
- character redesign.

If the grip or carrying system does not fit the character, redesign the weapon interface.

Never redesign the character.

---

# 3. OPTIONAL OUTFIT FREEZE

When an outfit is supplied as authoritative, preserve:

- sleeves;
- cuffs;
- gloves;
- gauntlets;
- shoulder masses;
- waist structures;
- belts;
- harnesses;
- capes;
- skirts;
- coats;
- armor;
- accessory placement;
- material architecture;
- color architecture;
- silhouette.

The weapon must account for the actual outfit.

A large guard cannot intersect a frozen gauntlet without resolution.

A scabbard cannot pass through a frozen cape.

A shoulder-mounted object cannot erase a frozen wing root.

A carrying system may attach to the outfit only where visually coherent.

Do not redesign the outfit merely to make the weapon convenient.

# 4. CREATIVE OBJECTIVE

The task is not:

**add a fantasy weapon.**

The task is:

**author a premium signature weapon that looks as though it belongs specifically to this character.**

The weapon should strengthen the character through:

- silhouette;
- scale;
- category choice;
- geometry;
- material architecture;
- color architecture;
- handling interface;
- visual rhythm;
- asymmetry;
- negative space;
- internal structure;
- secondary detail;
- relation to body and outfit.

A generic weapon with matching colors or a copied symbol fails.

If the weapon could be handed unchanged to an unrelated character without losing meaning, authorship is insufficient.

# 7. SIMPLE CONVENTIONAL VISUAL BASE — ABSOLUTE RULE

Every weapon begins internally from a simple, immediately readable base of the selected category.

Examples:

- sword → blade + edge(s) + point + guard where applicable + grip + terminal;
- spear → head + attachment/socket + shaft + end treatment;
- polearm → readable head + shaft + grip region + end;
- axe → head + cutting region + back/poll region where applicable + haft;
- hammer → striking mass + handle;
- scythe → curved blade + junction + shaft;
- bow → limbs + riser/grip + string;
- shield → primary plate/body + grip/arm interface;
- whip/chain → flexible main line + handle + terminal structure;
- science-fiction firearm-like prop → main body + grip/interface + barrel/emitter-like visual axis + stock/brace where applicable;
- staff → shaft + grip zones + terminal/head structure if present.

The base is an internal design scaffold.

It is not a separately generated required image.

Character-specific complexity is added only after category readability is secured.

---

# 8. CATEGORY READABILITY LOCK

Once selected, the weapon must remain unmistakably that category.

Radical transformation is allowed in:

- proportions;
- materials;
- internal geometry;
- negative space;
- guard/head construction;
- segmentation;
- asymmetry;
- inset systems;
- surface architecture;
- secondary components.

But the final silhouette must still communicate its category immediately.

If the weapon stops reading as the selected category and becomes an undefined decorative object, simplify the macro design.

# 9. SIMPLE MACRO / INTRICATE MICRO — ABSOLUTE

Macro includes:

- primary silhouette;
- category-defining components;
- overall length-to-width impression;
- directional geometry;
- major component relationships;
- grip position;
- major negative spaces;
- major asymmetry.

Macro must remain:

- clean;
- readable;
- economical;
- iconic;
- immediately understandable.

## Micro

Micro may include:

- bevel lines;
- fullers;
- channels;
- structural recesses;
- fine segmentation;
- engravings;
- incisions;
- inlays;
- nested borders;
- small apertures;
- material transitions;
- bounded luminous structures;
- compact mechanical articulation;
- localized ornament;
- small projections;
- fine internal supports.

Complexity belongs primarily in micro and secondary architecture.

Do not achieve “legendary” quality by adding endless giant spikes, wings, rings, branches, floating fragments, or unrelated silhouette masses.

---

# 10. CHARACTER-SPECIFIC WEAPON AUTHORSHIP

A signature weapon must establish concrete visual relationships with the character.

Possible relationships include:

- scale matched to body;
- geometry echoing character structure;
- transformed repetition of shape language;
- negative space derived from established body geometry;
- material relation;
- contrasting material relation;
- color relation;
- controlled palette counterpoint;
- grip designed for actual hands;
- compatibility with claws / extra digits / gloves;
- asymmetry related to character asymmetry;
- carrying logic related to outfit;
- edge rhythm related to outfit panels;
- internal segmentation related to body or garment segmentation;
- structural response to wings / tails / appendages.

Do not copy every character motif onto the weapon.

Choose one or two strong primary relationships and a small number of subordinate ones.

---

# 11. WEAPON / CHARACTER SEPARATION

The weapon must remain physically distinct.

It must not accidentally become:

- anatomy;
- a body appendage;
- a garment panel;
- armor;
- environmental architecture;
- a magical effect with no weapon body.

Wearable or mounted integration is permitted only when the weapon remains visually separable and readable as its own system.

---

# 12. SCALE AND CHARACTER BALANCE

Resolve weapon scale relative to the actual character.

Allowed:

- compact;
- medium;
- oversized;
- monumental;
- paired;
- asymmetrically paired;
- long;
- broad;
- narrow.

No scale is universally superior.

Large weapons must not automatically dominate the entire character.

Small weapons must not become visually irrelevant.

The combined silhouette should read as:

**character first + signature weapon second**, unless the user explicitly requests a weapon-dominant presentation.

Resolve visually, as applicable:

- grip count;
- grip location;
- one-handed / two-handed / paired logic;
- handle length impression;
- handle thickness impression;
- handle cross-section impression;
- wrapping;
- plating;
- segmentation;

- hand clearance;
- glove clearance;
- gauntlet clearance;
- claw clearance;
- extra-digit clearance;
- sleeve clearance;
- attachment points;
- carrying interface.

Do not solve interface problems by changing the character's hands or clothing.

This remains visual concept design, not real-world ergonomic specification.

# 14. BLADED-WEAPON VISUAL RESOLUTION

For bladed categories, resolve visually:

- blade profile;
- straight / curved architecture;
- single / double / localized edge logic;
- point/tip shape;
- taper;
- spine/back geometry;
- bevel / flat relationships where visible;
- ricasso-like unsharpened region where appropriate;

# 15. POLE / HAFT / STAFF WEAPON RESOLUTION

For polearms, spears, glaives, staffs, axes, hammers, and related categories, resolve:

- shaft proportion;
- grip zones;
- central balance impression;
- head geometry;
- butt/end treatment;

- material transitions;
- joining architecture;
- decorative systems subordinate to category.

---

# 16. BOW / FLEXIBLE WEAPON RESOLUTION

For bows, whips, chains, flexible or tension-based fictional weapons, preserve immediate category readability.

Resolve visually:

- primary line/limb architecture;
- grip/riser or handle;
- string/chain/whip continuity;
- terminal structures;
- segment rhythm;
- material behavior;
- flexibility cues;
- asymmetry where intentional;
- bounded secondary detail.

Do not replace the core flexible architecture with floating fragments or effects.

---

# 17. PAIRED-WEAPON SYSTEMS

A paired system counts as one weapon candidate when explicitly designed as a pair.

Pairs may be:

- mirrored;
- complementary;
- asymmetric;
- large/small;
- different but visually related.

The pair must read as a deliberate system.

Do not simply duplicate one item and flip it unless symmetry is the actual design.

When asymmetric, establish a clear relationship through:

- shared material;
- shared geometry;
- complementary negative space;
- color logic;
- reciprocal forms;
- related grip systems.

---

# 18. HYBRID / TRANSFORMING FICTIONAL WEAPONS

Hybrid or transforming designs are allowed when requested or genuinely useful.

Requirements:

- each visual state must remain readable;
- parent categories must not collapse into noise;
- the transformation relationship must be visually understandable at concept-art level;
- one form may not silently redesign the frozen character/outfit;
- transformation complexity must not destroy simple macro readability.

Do not supply real-world functional mechanisms, manufacturing instructions, or operational engineering.

The workflow governs visual design only.

# 20. COLOR ARCHITECTURE

# 25. PREMIUM SIGNATURE-WEAPON GATE

Before generation, ask internally:

- Does the weapon category read instantly?
- Is the macro silhouette iconic?
- Does it look specifically authored for this character?
- Does it strengthen the character's combined silhouette?
- Would it be recognizable when isolated?
- Are materials structural?
- Is color intentional?
- Is the grip/interface visually compatible?
- Is micro-detail subordinate?
- Does it avoid generic inventory-item appearance?
- Could it plausibly function as a premium character signature prop in key art, figures, skins, or fan art?

If not, refine before rendering.

When the user broadly asks for weapons, weapon ideas, or “suggest weapons” without fixing one exact design, create **10 structurally distinct candidates**.

## Mandatory output geometry

- two rows of five;
- plain white or very light neutral background;
- candidates numbered 1–10;
- isolated complete weapons;
- no character holding them;
- no scene;
- no environment;
- no narrative text;

A paired system counts as one candidate and displays both members coherently.

# 27. CATALOGUE DIVERSITY

If category is not fixed, use a broad category mix where suitable.

# 30. COMMAND ROUTING

## SUGGEST WEAPONS / WEAPONS
Generate the default ten-candidate catalogue.

## CREATE: [directive]
Create one new weapon from the directive.
Default output: isolated complete weapon on a neutral presentation, with aspect ratio chosen for readability unless the user specifies one.

## PREVIEW [candidate]
Render the selected weapon together with the frozen character.

Default:
- one full-body character;
- selected weapon clearly visible;
- neutral or minimally posed;
- plain white/light-neutral background;
- no scene;
- no extra effects unless intrinsic to the weapon;
- exact frozen character/outfit.

## REFINE [candidate/current]
Improve weapon quality while preserving category and recognizable weapon identity.

## ALTER [candidate/current]: [instruction]
Change only the requested design dimensions and necessary dependent construction.

## FUSE [A] + [B] (+ ...)
Create one new coherent weapon by structurally synthesizing selected candidate systems.

## VARIANTS [candidate/current]: [dimension]
Create controlled derivatives preserving core identity.

## CONSTRUCTION [candidate/current]
Produce a clean visual reference showing only the minimum views needed to reconstruct the weapon's geometry.

## FREEZE [candidate/current]
Freeze the selected weapon state for the active conversation.

# 33. CONSTRUCTION VIEW CONTRACT

When CONSTRUCTION is requested, use the minimum useful set.

For many weapons:

- one large primary orthographic view;
- optional second view if thickness/back geometry matters;
- optional third view only if it reveals genuinely hidden construction;
- up to two focused detail crops when necessary.

Do not create redundant views.

Long weapons may use a landscape construction sheet.

Paired systems must show both members.

The exact frozen weapon design must remain identical across views.

# 34. FUSION QUALITY GATE

Fusion must identify source contributions at the system level.

Possible contributions:

- category;
- silhouette;
- proportion;
- blade/head geometry;
- guard;
- grip;
- negative space;
- material system;
- color strategy;
- asymmetry;
- inset architecture;
- micro-detail language.

Fusion is not:

- left half A + right half B;
- attaching B's gem to A;
- averaging;
- random collage;
- simply recoloring one parent.

Resolve one new coherent weapon.

At least one higher-order synthesis should emerge.

---

# 35. ALTERATION PRESERVATION GATE

ALTER changes only what is requested.

Examples:

- “make the blade broader” → preserve guard, grip, palette, and other identity-defining systems unless dependent adjustment is necessary;
- “remove the gem” → redesign only the local inset architecture needed for coherence;
- “make it more asymmetrical” → preserve category and major proportions;
- “more black” → preserve structure;
- “shorter” → preserve internal identity while resolving proportion dependencies.

Do not opportunistically redesign the whole weapon.

---

# 36. REFINEMENT GATE

REFINE is not REDESIGN.

Refinement may improve:

- proportion balance;
- silhouette clarity;
- character relationship;
- interface clarity;
- material readability;
- color balance;
- internal detail;
- border quality;
- segmentation;
- asymmetry;
- micro-detail hierarchy;
- render robustness.

The weapon must remain recognizably the same design.

# 40. FAILURE CONDITIONS — HARD

A weapon fails if any of the following occurs:

- wrong category;
- category unreadable;
- generic inventory-item design;
- simple macro destroyed by silhouette clutter;
- character/outfit redesigned to fit the weapon;
- weapon merges into anatomy;
- weapon merges into clothing;
- grip incompatible with visible character anatomy;
- structural material reduced to glow/coating;
- random holes or rings;
- arbitrary decorative scatter;
- same-category candidates differ only by color;
- repeated template architecture;
- detached effects define the weapon shape;
- weapon cropped;
- paired member omitted;
- wrong candidate count;
- catalogue not 16:9 two-by-five when required;
- background not plain/light neutral;
- extra character in isolated catalogue;
- narrative labels or epithets;
- 3D/PBR drift;
- micro-detail overwhelms macro;
- unrequested giant additions;
- frozen character identity drift in preview;
- frozen outfit drift in preview.

Pre-generation failure:
**STOP → REDESIGN → REVALIDATE → GENERATE.**

Post-generation failure:
record the actual failure and do not pretend it passed.

# 42. FINAL ACCEPTANCE STANDARD

A successful weapon must be:

- immediately category-readable;
- character-specific;
- visually iconic;
- coherent;
- structurally resolved as visual design;
- simple in macro;
- intricate in micro;
- materially deliberate;
- color-authored;
- interface-aware;
