# MUTATION CREATION — ABSOLUTE AUTHORITATIVE CREATIVE WORKFLOW

## Version 1.0 — Controlled-Deviation / Identity-Retention / Branching-Morphology Workflow

**STATUS:** AUTHORITATIVE / STANDALONE / SOURCE-ANCHORED / CONTROLLED-STOCHASTIC / HIGH-VARIATION / STRUCTURAL / IMAGE-CAPABLE

This document is the sole authoritative Mutation Creation workflow for the active conversation.

Its purpose is to take an established character or creature and deliberately mutate selected visual systems to create one or more coherent variants, offshoots, altered states, or descendant designs while controlling exactly how much source identity is preserved.

Mutation is not random corruption.

Mutation is not a recolor.

Mutation is not a generic monster pass.

Mutation is **controlled creative deviation from an established source design**.

---

# 0. HIGHEST-PRECEDENCE EXECUTION LOCK

Mutation Creation follows:

**SOURCE DESIGN → SOURCE-ANCHOR EXTRACTION → PROTECTED-ANCHOR LOCK → RETENTION TARGET → MUTATION PRESSURE → MUTATION-VECTOR SELECTION → STRUCTURAL PROPAGATION → MATERIAL / COLOR / MORPHOLOGY DIFFERENTIATION → COHERENCE AUDIT → SOURCE-RELATION AUDIT → RENDER PREFLIGHT → IMAGE GENERATION → ACTUAL-IMAGE INSPECTION → USER SELECTION / BRANCH / REFINE / ALTER / FUSE / FREEZE**

The source design is always the origin.

The workflow may preserve a large amount of identity or deliberately move far away from it.

The amount of deviation is controlled explicitly.

The renderer is never allowed to decide randomly how much identity to destroy.

---

# 1. REQUIRED INPUT

A normal Mutation Creation task requires a source design.

Valid source authorities include:

- character illustration;
- Character Sheet;
- frozen Character Creation output;
- frozen Feminisation output;
- transformed character form;
- creature illustration;
- creature reference sheet;
- another explicit visual design supplied by the user.

Optional inputs:

- mutation directive;
- mutation percentage;
- protected features;
- forbidden changes;
- concepts;
- materials;
- anatomical targets;
- mutation references;
- Art Style Sheet;
- outfit or weapon references.

If no mutation directive is supplied, the workflow may invent mutation directions internally while obeying the source-preservation and diversity rules.

---

# 2. MUTATION VS TRANSFORMATION — ABSOLUTE DISTINCTION

Transformation asks:

**What alternate form can this same character deliberately become?**

Mutation asks:

**How can this source design deviate, branch, distort, recombine, or evolve while preserving a controlled amount of lineage?**

Transformation normally protects same-character identity strongly.

Mutation may produce:

- same-character mutant states;
- unstable altered versions;
- divergent variants;
- sibling-like offshoots;
- evolutionary branches;
- derivative population designs;
- heavily altered descendants.

Do not silently convert Mutation into Transformation.

Do not force every mutant to remain equally recognizable.

Identity retention is an explicit parameter.

---

# 3. SOURCE-ANCHOR EXTRACTION

Before mutation, identify the source design's major visual systems.

Potential source anchors include:

- face geometry;
- eye geometry;
- eye color;
- hairline;
- bangs;
- hairstyle architecture;
- hair color;
- body proportions;
- height impression;
- shoulder structure;
- torso length;
- chest architecture;
- waist;
- pelvis and hips;
- limb proportions;
- skin tone;
- species traits;
- horns;
- wings;
- ears;
- tail;
- appendages;
- body materials;
- markings;
- scars;
- asymmetry;
- silhouette;
- outfit landmarks;
- signature accessories;
- dominant color relationships;
- major negative spaces;
- recurring geometry.

These anchors are classified internally as:

## PROTECTED
Cannot mutate unless the user explicitly unlocks them.

## STABLE
Should remain recognizable but may deform moderately.

## FLEXIBLE
May mutate substantially.

## OPEN
May be replaced completely.

The user may override any classification.

---

# 4. PROTECTED-ANCHOR LOCK

Protected anchors are absolute.

If the user says:

- keep the face;
- keep the hair;
- preserve the eyes;
- preserve the body type;
- keep the wings;
- do not alter the outfit;
- keep the silhouette;
- preserve the skin tone;

those features become immutable until explicitly unlocked.

Mutation pressure must route around protected systems.

Never “approximately preserve” a protected anchor.

Preserve it.

---

# 5. IDENTITY-RETENTION SCALE

Mutation uses an explicit retention percentage.

Default when unspecified:

**70% source retention / 30% mutation**

This is the standard balanced Mutation mode.

## 90% RETENTION
Subtle mutant variant.

Changes may affect:
- localized anatomy;
- markings;
- eyes;
- small appendages;
- material patches;
- hair details;
- asymmetry;
- color accents.

Source identity remains dominant.

## 70% RETENTION
Balanced mutation.

Major systems may change, but the source remains clearly traceable.

Suitable for:
- alternate mutant version;
- strong corruption;
- evolutionary branch;
- sister variant;
- experimental redesign.

## 50% RETENTION
Equal source/mutation balance.

The result should visibly descend from the source but may no longer read as exactly the same individual.

Suitable for:
- derivative character;
- close lineage;
- major evolutionary branch;
- population diversification.

## 30% RETENTION
Mutation dominant.

Only selected source anchors remain.

Suitable for:
- distant derivative;
- heavily divergent branch;
- source-inspired species variant;
- descendant design.

## BELOW 30%
Use only when explicitly requested.

The result may become a highly distant derivative.

At this level, do not falsely claim it remains the same character.

---

# 6. RETENTION MUST BE VISUAL, NOT NUMERICAL THEATER

A “70% retention” instruction is not a mathematical pixel calculation.

It is a design-control target.

Retention should be distributed across meaningful visual systems.

For example, a 70% mutant may preserve:

- face;
- bangs;
- body proportions;
- one signature appendage;
- core palette relationship;

while mutating:

- arms;
- skin material;
- eyes;
- secondary appendages;
- outfit;
- asymmetry.

Do not merely keep 70% of the body unchanged by area.

Preserve 70%-equivalent **identity value**.

---

# 7. MUTATION PRESSURE

Mutation pressure describes how aggressively the selected mutable systems should deviate.

## LOW PRESSURE
Small deviations within the source's existing design language.

## MEDIUM PRESSURE
Substantial structural change while maintaining clear lineage.

## HIGH PRESSURE
Strong morphological deviation, recombination, asymmetry, material change, or species shift.

## EXTREME PRESSURE
Radical redesign of all unlocked systems while protecting only explicit anchors and retention requirements.

Pressure and retention are related but not identical.

A high-pressure mutation can still preserve a protected face and hair.

# 9. MULTI-VECTOR SYMBIOSIS — HARD

When several mutation vectors are used, do not isolate them into separate decorative regions.

Weak:
- crystal arm;
- plant hair;
- metal boots.

Strong:
- crystalline growth determines joint segmentation;
- plant-like fibers form connective structures around the crystal;
- metallic plates develop where those fibers anchor;
- the same geometry repeats through the silhouette.

Mutation vectors must influence one another.

The result should read as one organism/design system.

---

Glow, aura, color grading, particles, and background effects do not constitute a meaningful mutation by themselves.

---

# 11. LOCAL VS SYSTEMIC MUTATION

Mutation may be localized or systemic.

## LOCAL
Affects one region strongly.

Examples:
- one arm;
- face;
- back;
- legs;
- one eye;
- torso;
- one side of the body.

## SYSTEMIC
Propagates through multiple body regions.

Examples:
- crystalization spreads through limbs and torso;
- biomechanical segmentation appears across joints;
- floral growth changes hair, skin, appendages, and silhouette.

The user may specify either.

If unspecified, choose the distribution that best serves the mutation concept.

---

# 12. ASYMMETRY IS A PRIMARY MUTATION TOOL

Mutation may use strong asymmetry.

Examples:

- one enlarged arm;
- one transformed leg;
- unilateral horn growth;
- one wing;
- one side crystallized;
- one eye altered;
- mutation spreading from one origin point;
- asymmetric plating;
- side-biased appendages.

Asymmetry should have design logic.

Do not create accidental left/right inconsistencies.

---

# 13. FACE MUTATION

Face mutation is high impact.

Possible changes:

- markings;
- eye mutation;
- sclera changes;
- altered pupils;
- material patches;
- scales;
- plating;
- cracks;
- secondary eyes;
- horn bases;
- mouth/teeth changes;
- facial asymmetry.

At high retention levels, preserve core face geometry.

At lower retention levels, face geometry may drift more substantially if enough lineage remains elsewhere.

Do not default to a generic monster face.

---

# 14. EYE MUTATION

Eyes are powerful mutation carriers.

Possible changes:

- iris color;
- iris pattern;
- multiple pupils;
- slit pupils;
- luminous structure;
- black sclera;
- extra eyes;
- mechanical lenses;
- crystalline iris;
- segmented iris;
- asymmetrical eye mutation.

Do not randomly introduce heterochromia unless selected as part of the mutation.

Eye changes should reinforce the mutation system.

---

# 15. HAIR MUTATION

Hair may mutate through:

- length;

- volume;

- liquid-like strands;

- overgrowth.

At higher retention levels, preserve source bangs, parting, or face-framing architecture when identity-critical.

---

# 19. COLOR ARCHITECTURE — HARD

Mutation must actively use color architecture.

Avoid:
- one hue across skin, hair, eyes, appendages, outfit, and effects;
- one generic black/red corruption palette for every mutant;
- one generic white/blue “divine” palette.

Use combinations such as:

- bicolor;
- tricolor;
- gradient zones;
- warm/cool split;
- complementary accents;
- material-dependent colors;
- localized bioluminescence;
- asymmetric color distribution;
- inherited source colors plus novel mutation colors.

Color should help reveal which systems are inherited and which are mutated.

---

# 20. MATERIAL DIFFERENTIATION

Different systems must read as different materials where appropriate.

Examples:
- crystal shell vs organic skin;
- chitin vs cloth;
- bone strut vs membrane;
- metal plate vs synthetic muscle;
- bark vs leaf tissue.

Shared hue does not justify shared material appearance.

---

# 21. OUTFIT HANDLING

By default, treat the source outfit as a separate system.

Possible modes:

## PRESERVE
Outfit remains unchanged.

## ADAPT
Only necessary clearances/openings change.

## MUTATE
Outfit participates in the mutation.

## REPLACE
Outfit may be redesigned as part of the mutant variant.

The user may specify the mode.

If unspecified:
- same-character high-retention mutation → PRESERVE or ADAPT;
- derivative low-retention branch → ADAPT or MUTATE as appropriate.

Do not silently erase clothing.

---

# 22. WEAPON HANDLING

Weapons are separate unless the user includes them in the mutation.

Default:
- preserve or omit from mutation presentation.

Do not silently fuse the weapon into anatomy.

Do not transform the weapon merely because the body mutated.

Weapon mutation requires explicit authorization.

---

# 23. SILHOUETTE MUTATION

A mutation should normally create visible silhouette change when pressure is medium or higher.

Possible silhouette mutations:

- asymmetric arm mass;
- altered shoulders;
- back structures;
- wings;
- tails;
- horn profile;
- hair growth;
- altered legs;
- external plating;
- protrusions;
- extra limbs.

Avoid universal “bigger shoulders + horns” mutation shorthand.

Silhouette should arise from the specific vector.

---

# 24. MUTATION ORIGIN LOGIC

A mutation may have an origin region.

Examples:
- left hand;
- chest;
- eye;
- spine;
- lower body;
- face;
- tail root.

If an origin is used, propagation should make visual sense.

Possible propagation patterns:
- radial spread;
- vein-like spread;
- segmented spread;
- material-front spread;
- asymmetric creep;
- branching growth;
- joint-to-joint conversion.

This is visual logic, not medical or biological instruction.

---

# 25. COHERENCE HIERARCHY

Strong mutants need hierarchy.

Choose:

- one dominant mutation system;
- one or two secondary systems;
- tertiary echoes.

Do not mutate every feature with equal visual intensity.

Too many equally loud changes produce noise rather than design.

---

# 26. DEFAULT FIVE-CANDIDATE MUTATION CATALOGUE

When the user broadly asks for mutations, variants, mutant ideas, or “mutate this” without specifying one exact result, create **5 radically distinct mutation candidates**.

## Mandatory catalogue geometry

- one continuous exact **16:9 landscape** image;
- five complete full-body candidates;
- plain white or very light neutral background;
- candidates numbered 1–5;
- no narrative names;
- no lore text;
- no environment;
- no unrelated props;
- no decorative UI;
- no extra characters.

Use a consistent neutral or minimally posed stance to make mutation structure comparable.

Default retention:
**70% source / 30% mutation**

unless the user specifies otherwise.

---

# 27. CANDIDATE DIVERSITY — HARD

The five candidates must differ across several axes:

- mutation vector;
- mutation origin;
- mutated regions;
- silhouette;
- material architecture;
- appendages;
- asymmetry;
- eye treatment;
- hair treatment;
- color architecture;
- outfit relationship;
- dominant mutation system.

Do not create five colorways of one mutant.

Do not create five versions of the same horn/wings/tail formula.

---

# 28. RANDOMNESS RULE

Mutation may use controlled unpredictability.

However:

- randomness chooses among valid design possibilities;
- randomness never overrides protected anchors;
- randomness never overrides retention;
- randomness never creates incoherent anatomy;
- randomness never replaces design judgment.

The workflow may surprise the user.

It may not become arbitrary.

---

# 29. COMMAND ROUTING

## MUTATE: [directive]
Create one mutation.

If no retention is specified, use 70%.

## MUTATE [X%]
Create one mutation at the requested source-retention percentage.

## SUGGEST MUTATIONS / MUTATIONS
Create the default five-candidate catalogue.

## PROTECT: [features]
Add features to the protected-anchor set.

## UNLOCK: [features]
Allow previously protected features to mutate.

## PRESSURE: LOW / MEDIUM / HIGH / EXTREME
Set mutation pressure.

## RETENTION: [percentage]
Change source-retention target.

## PREVIEW [candidate]
Render the selected mutant as a large 9:16 full-body presentation.

## REFINE [candidate/current]
Improve coherence, morphology, transitions, color, and design quality while preserving mutant identity.

## ALTER [candidate/current]: [instruction]
Change only the requested mutant system and necessary dependencies.

## FUSE [A] + [B] (+ ...)
Create a new mutant by structurally recombining selected candidate systems.

## BRANCH [candidate/current]
Create a new set of descendants derived from the selected mutant rather than the original source.

## RESEED [candidate/current]
Keep the same retention, protected anchors, and mutation vector, but explore a substantially different structural realization.

## REVERT [system]
Restore one system toward the source design.

## FREEZE [candidate/current]
Freeze the selected mutant state.

---

# 30. BRANCHING — CORE MUTATION CAPABILITY

BRANCH creates descendants from the current mutant.

The current mutant becomes the new local source.

Branching may be repeated:

**SOURCE → MUTANT A → A1 / A2 / A3 → A2.1 / A2.2 ...**

Each branch must record internally:

- inherited anchors;
- newly protected features;
- mutable features;
- retention relative to its immediate parent;
- retention relative to the original source where relevant.

Do not silently forget the original lineage.

---

# 31. BRANCH CATALOGUE

Default BRANCH output:

- 5 descendants;
- exact 16:9 landscape;
- complete full-body designs;
- same background and presentation rules as the standard mutation catalogue.

Branches should preserve the parent mutant's strongest new identity while exploring additional deviation.

A branch is not a return to the original source unless explicitly requested.

---

# 32. FUSION QUALITY GATE

Fusion operates at system level.

Possible inherited systems:

- face treatment;
- eye mutation;
- hair mutation;
- arm mutation;
- body material;
- appendages;
- color system;
- asymmetry;
- silhouette;
- outfit mutation.

Do not produce arbitrary left-half/right-half collage.

Do not simply stack both parents' appendages.

Resolve one coherent new mutant.

At least one emergent relationship must appear from the synthesis.

---

# 33. ALTERATION PRESERVATION GATE

ALTER changes only what the user requests.

Examples:

- “make the mutated arm larger” → preserve face, hair, legs, palette, and other systems;
- “remove the extra eye” → repair local facial architecture only;
- “more crystalline” → increase crystal materialization without replacing unrelated organic systems;
- “restore the hair” → return hair toward source while preserving other mutations;
- “make it less asymmetric” → rebalance only necessary affected systems.

Do not opportunistically redesign the entire mutant.

---

# 34. REFINEMENT GATE

REFINE is not REDESIGN.

Refinement may improve:

- mutation coherence;
- material transitions;
- appendage roots;
- body integration;
- silhouette clarity;
- retention accuracy;
- protected-anchor fidelity;
- color architecture;
- asymmetry quality;
- micro-detail;
- render robustness.

The mutant must remain recognizably the same mutant design.

---

# 35. RESEED GATE

RESEED preserves:

- source;
- retention target;
- protected anchors;
- mutation pressure;
- vector;
- broad mutation intent.

But it creates a substantially different structural realization.

Use RESEED when the direction is right but the specific design is not.

RESEED is not a minor variation.

---

# 36. SINGLE-MUTANT PREVIEW CONTRACT

Default:

- exact **9:16 portrait**;
- one full-body mutant;
- plain white/light-neutral background;
- neutral or minimally posed;
- complete silhouette;
- no scene;
- no text;
- no unrelated props;
- no extra characters;
- source identity preserved according to retention target.

The image exists to evaluate the mutant itself.

---

# 37. STYLE HANDLING

If an Art Style Sheet is supplied:

**ART STYLE SHEET = rendering authority only.**

The source design and mutation specification remain content authorities.

If no Art Style Sheet is supplied, use a clean high-quality 2D anime/manhwa rendering compatible with the source.

Do not let style change substitute for mutation.

---

# 38. GENERATOR HANDOFF

Before generation, serialize in this order:

1. source identity;
2. protected anchors;
3. retention percentage;
4. mutation pressure;
5. mutation vector(s);
6. mutated regions;
7. preserved regions;
8. morphology;
9. materials;
10. appendages;
11. asymmetry;
12. color architecture;
13. outfit handling;
14. weapon handling;
15. exact output geometry;
16. exclusions.

The renderer must not decide which source features survive.

That decision belongs to the workflow before rendering.

---

# 39. ACTUAL-IMAGE INSPECTION

After generation, inspect the actual image.

Check:

- source lineage visible at intended retention;
- protected anchors preserved exactly enough;
- mutation pressure appropriate;
- mutation is structural, not merely effects;
- materials read as materials;
- appendages have coherent roots;
- body transitions are integrated;
- asymmetry intentional;
- silhouette changed appropriately;
- color architecture differentiated;
- outfit handled according to mode;
- weapon handled correctly;
- no accidental generic monster substitution;
- no unintended sex/gender drift;
- no source features lost beyond retention budget;
- no important mutant systems omitted;
- output geometry correct.

Do not assume prompt compliance.

---

# 40. FAILURE CONDITIONS — HARD

Failure includes:

- protected anchor changed;
- retention significantly lower than requested;
- retention significantly higher than requested in a supposedly strong mutation;
- mutation reduced to color/effects;
- generic monster replacement;
- same mutant repeated across candidates;
- concepts stacked without integration;
- appendages pasted on without roots;
- body material represented only as a shader;
- every system same color by default;
- accidental sex/gender drift;
- anatomy changes unrelated to mutation vector;
- source outfit silently erased;
- source weapon silently transformed;
- branch forgets parent identity;
- RESEED produces only a recolor;
- fusion is a collage;
- extra characters;
- catalogue count wrong;
- catalogue geometry wrong;
- critical anatomy cropped;
- scene/background added.

Pre-generation failure:
**STOP → REDESIGN → REVALIDATE → GENERATE.**

Post-generation failure:
record the actual failure and do not pretend it passed.

---

# 41. FREEZE SEMANTICS

A frozen mutant locks:

- original source;
- local parent if branched;
- protected anchors;
- retention target;
- mutation pressure;
- mutation vectors;
- morphology;
- materials;
- appendages;
- asymmetry;
- silhouette;
- eye treatment;
- hair treatment;
- color architecture;
- outfit mode;
- weapon mode;
- identity-defining mutant details.

Freeze prevents silent drift.

Explicit ALTER, REFINE, FUSE, BRANCH, RESEED, REVERT, or new MUTATE commands create a new revision.

---

# 42. FINAL ACCEPTANCE STANDARD

A successful mutant must be:

- recognizably descended from the source to the requested degree;
- clearly different;
- structurally mutated;
- visually coherent;
- materially resolved;
- color-authored;
- non-generic;
- internally consistent;
- visually memorable;
- reproducible.

At high retention, the viewer should think:

**“That is the same character, mutated.”**

At medium retention:

**“That clearly comes from that character.”**

At low retention:

**“That is a distant but traceable descendant of that design.”**

---

# 43. FINAL COMMAND

For every Mutation Creation task:

**Extract the source identity.  
Lock protected anchors.  
Set retention deliberately.  
Set mutation pressure deliberately.  
Choose mutation vectors.  
Materialize mutation structurally.  
Integrate multiple vectors symbiotically.  
Use asymmetry, morphology, material, silhouette, and color as real design systems.  
Do not rely on effects.  
Do not mutate protected systems.  
Do not let randomness override authorship.  
Differentiate candidates radically.  
Branch coherently.  
Render only resolved mutants.  
Inspect the actual image.  
Freeze accepted mutants against silent drift.**

The target is not random distortion.

The target is:

**controlled evolutionary design — a source-derived mutant whose degree of lineage and degree of deviation are both deliberate.**
